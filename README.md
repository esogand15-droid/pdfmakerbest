# HumsYar PDF Engine — موتور جزوه‌ساز هامزیار

موتور تولید جزوات علوم پایهٔ پزشکی: «جزوهٔ مادر» هر جلسه را به PDF نهایی حرفه‌ای تبدیل می‌کند —
مدل محتوای ساختاریافته + Design System فارسی/RTL + موتور چیدمان + رندر Chromium + QA خودکار.

گزارش ممیزی و تصمیم‌های معماری: [`docs/AUDIT.md`](docs/AUDIT.md) · مشخصات پروژه: [`docs/AGENT_PROMPT.md`](docs/AGENT_PROMPT.md)

## اجرای سریع

```bash
python3 -m venv .venv && .venv/bin/pip install -r engine/requirements.txt pillow
cd engine && npm install        # puppeteer-core + Chromium بسته‌بندی‌شده (آفلاین‌پسند)
# اگر Chrome سیستمی دارید، به‌جای npm کافی است: export CHROME_PATH=/path/to/chrome

# ساخت پایلوت (جلسهٔ ۱، مباحث ۴ و ۶)
../.venv/bin/python -m humsyar.cli build ../content/session01_pilot.yaml --edition final --out ../output

# تست‌ها
cd .. && .venv/bin/python -m pytest tests/ -q
```

خروجی‌ها در `output/`: فایل PDF، نسخهٔ HTML، `build_report.json` (تصمیم‌های چیدمان + QA)،
`review_report.md` (موارد نیازمند بازبینی انسانی) و رندر تصویری صفحات در `output/pages/`.

## گزینه‌های ساخت

| پرچم | مقادیر | پیش‌فرض | توضیح |
|---|---|---|---|
| `--edition` | `final` / `workbook` | `final` | workbook کادرهای یادداشت تیم را نگه می‌دارد |
| `--theme` | `a` / `b` | `a` | A: تیل بالینی · B: سرمه‌ای تحریریه‌ای (فقط توکن رنگ) |
| `--no-sources` | — | خاموش | پنهان‌کردن برچسب‌های منبع |

## استخراج از جزوهٔ مادر

```bash
../.venv/bin/python -m humsyar.cli extract ../HumsYar_NeuroAnat_Jalase1.pdf --out ../audit/s01
```

خروجی «پیش‌نویس استخراج» است (متن با ترتیب منطقی بازسازی‌شده + تصاویر اصلی + فهرست وضوح)؛
ساختاربندی آن به YAML گام ویرایشی جداست و وضعیت همهٔ بلوک‌ها تا تأیید تیم `needs_review` می‌ماند.

## افزودن جلسهٔ جدید

۱) استخراج (بالا) ← ۲) ساختاربندی در `content/sessionXX.yaml` با همان قرارداد بلوک‌ها ←
۳) `build` ← ۴) خواندن `review_report.md` و رندر صفحات ← ۵) تأیید علمی و تغییر وضعیت بلوک‌ها به `approved`.
هیچ تغییری در کد لازم نیست.

## قرارداد محتوای YAML (خلاصه)

هر بلوک: `id` پایدار، `type`، `status` (`extracted|editorial|needs_review|approved|unresolved_conflict`)،
`sources: [{book, pages, figure}]` و فیلدهای خودش. انواع بلوک: `section, paragraph, callout
(key|clinical|warning|bridge|conflict|exam), table, figure, process, dual_process, tree,
checklist, summary_box, team_note`.

نشانه‌گذاری درون‌متنی: `**برجسته**` · `[[term:فارسی|English]]` (اصطلاح دوزبانه) · `[en:Na+/K+-ATPase]` (لاتین ایزوله برای سلامت bidi).

**قانون محتوا:** موتور هرگز عدد/اصطلاح/مطلب علمی را تغییر نمی‌دهد و اختلاف منابع را حل نمی‌کند؛
ابهام‌ها در `review_report.md` ثبت می‌شوند.

## ساختار مخزن

```
content/            فایل‌های محتوای جلسات (YAML)
engine/humsyar/     model · planner · typeset · diagrams · build · qa · extract · cli
engine/themes/      Design System (CSS توکن‌محور)
engine/render.mjs   رندر Chromium
assets/fonts/       Vazirmatn (OFL — ببینید OFL.txt)
assets/figures/     تصاویر اصلی استخراج‌شده (دست‌نخورده)
tests/              تست‌های pytest (مدل، چیدمان، QA روی PDF واقعی، حقایق کنترلی)
docs/               ممیزی/معماری و مشخصات پروژه
output/             خروجی‌های ساخت
```

## راند ۲ — کاور، فهرست، قاب موضوعی و تراکم (نسخهٔ ۰٫۲ پایلوت)

**قانون برند:** تنها املای درست «هامزیار / HumsYar» است و از یک منبع مرکزی خوانده می‌شود:
`config/brand.yaml` (`engine/humsyar/brand.py`). تست خودکار برند روی متن PDF نهایی، متادیتا
و کل ریپو (به‌جز پرامپت آرشیوی کارفرما و استخراج‌های جزوهٔ مادر در `audit/` که سند تاریخی‌اند)
باید صفر باشد. لوگوی رسمی در ریپو وجود ندارد؛ برند صرفاً تایپوگرافیک است.

**خط لولهٔ جدید build:**
`validate → brand → بهینه‌سازی تصاویر نمایشی → planner v2 → measure (ارتفاع واقعی بلوک‌ها در Chromium) → packing (شبیه‌سازی صفحه‌بندی + اصلاح‌های مجاز) → رندر بدنه → شماره‌صفحه‌های واقعی فهرست → رندر نهایی بدنه → رندر جدا کاور و قاب → ادغام و مهر (PyMuPDF) → بوکمارک/متادیتا → QA`

- **کاور (ص.۱):** تمام‌صفحه (full-bleed)، هنر پارامتریک SVG با موتیف قابل‌پیکربندی هر جلسه
  (`session.cover_motif`؛ جلسهٔ ۱: `histology-neuron-glia` در `engine/humsyar/cover.py`).
  بدون قاب/شمارهٔ صفحه؛ در شمارش صفحات هست ولی شماره نمی‌گیرد. نشان «پایلوت موتور» فقط با `draft: true`.
- **فهرست (ص.۲ مستقل):** نقشهٔ جلسه + فهرست لینک‌دار با شماره‌صفحهٔ نهایی و نقطه‌چین +
  **تصمیم:** نوار فشردهٔ «چطور این جزوه را بخوانیم؟» پایین همین صفحه نشست (نه ابتدای ص.۳) چون صفحهٔ
  فهرست فضای کافی داشت و خواننده راهنما را پیش از شروع می‌بیند. پیوندها از مختصات واقعی
  اندازه‌گیری‌شده در مرورگر مهر می‌شوند.
- **قاب موضوعی (`session.frame_theme`؛ `engine/humsyar/frame.py`):** قاب دوخطه در اینسِت ۶mm،
  موتیف دندریت/سیناپس در گوشه‌ها (≤۱۱mm)، آکسون+میلین روی لبهٔ بالا، تب سربرگ روی خط بالا،
  کپسول شمارهٔ صفحه وسط خط پایین (فقط رقم فارسی، مهرشده با TextWriter). مقدار `none` پشتیبانی می‌شود.
- **عرض مفید صفحه:** حاشیهٔ داخلی ۱۴/۱۳mm → عرض مفید متن **۱۸۲mm** (راند ۱: ۱۷۸mm؛ +۴mm).
  ناحیهٔ امن QA: ‏(۱۲،۱۲) تا (۱۹۸،۲۸۵) میلی‌متر. قد مفید ≈ ۲۷۰mm.
- **قواعد تراکم پلنر v2:** سقف ارتفاع تصویر پهن ≈۸۶mm (۳۲٪)، عمودی/مربعی ≈۱۱۳mm (۴۲٪)،
  سقف سخت ≈۱۲۱٫۵mm (۴۵٪)؛ پیش‌فرض تصویر عمودی/مربعی: «کپشن‌کناری»؛ زوج‌شکل هم‌مبحث وقتی در
  نیم‌عرض خوانا بماند؛ `min_width_mm` برای شکل‌های برچسب‌دار؛ عملیات بسته‌بندی فقط: کوچک‌سازی
  در محدودهٔ خوانایی، جلوکشیدن بلوک مستقل از پنجرهٔ ۳تاییِ همان بخش (بدون شکستن ارجاع به شکل)،
  شکست کنترل‌شدهٔ جدول بزرگ. ترتیب معنایی و لینک تصویر-متن هرگز نمی‌شکند.
- **نتیجهٔ پایلوت:** ۱۳ صفحه (کاور+فهرست+۱۱ بدنه) در برابر ۱۶ صفحهٔ راند ۱؛ میانگین پُری صفحات
  محتوایی ≈۹۳٪ و هیچ صفحهٔ محتوایی زیر ۷۰٪ نیست (گزارش ریز در `output/build_report.json`).

**استثنای مستند برچسب‌های ریز:** در دو میکروگراف (`s01t6-f5` و `s01t6-f9`) برچسب‌های *داخل* تصویر
در هیچ اندازهٔ معقول چاپی به کف ۶٫۵pt نمی‌رسند (حتی تمام‌صفحه)؛ بنابراین کانال خوانایی، «چیپ‌های
دوزبانهٔ برچسب» کپشن است که همهٔ برچسب‌های متن مادر را با فونت خوانا بازمی‌نویسد. کف‌های حدسی
`min_width_mm` این دو شکل حذف شد تا چیدمان کپشن‌کناری کار کند؛ اصل تصویرها دست‌نخورده‌اند.

تست‌های راند ۲ در `tests/test_round2.py`: قانون برند (PDF+متادیتا+ریپو)، لینت همزهٔ اضافه،
نمونه‌برداری پیکسلی کاور، لینک‌های فهرست، رقم فارسی کپسول، ناحیهٔ امن قاب، سقف‌های پلنر،
قطعیت بسته‌بندی و معیارهای پُری.

## راند ۳ — ارتقای حرفه‌ای موتور (جدول‌ها، Preflight، هویت بصری لوگو)

نقشهٔ معماری و قراردادهای پایداری: [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md) ·
نسخهٔ مرجع مقایسه: `output/baseline_round2.pdf`

- **پالت هم‌خانوادهٔ لوگو (تم A پیش‌فرض):** توکن‌های `--navy:#0A0F1E; --dark:#0D1524; --blue:#2563EB;
  --blue-lt:#3B82F6; --teal:#14B8A6; --teal-br:#2DD4BF; --soft:#F0F6FF` مبنای سیستم‌اند و توکن‌های
  نقشی (مثل `--brand:#0B7A6E`) مشتق خوانای همان خانواده برای متن ریزند. زمینهٔ صفحات داخلی سفید؛
  تیره/نئونی فقط روی کاور.
- **لوگوی رسمی:** مسیرها در `config/brand.yaml` (`logo`، `logo_mono`، `favicon` → `assets/brand/`).
  کاور: لوگوی رنگی شفاف زیر عنوان (۲۸mm) + نام برند. سربرگ داخلی: نشان تک‌رنگ سرمه‌ای ۵٫۲mm کنار
  HumsYar. اگر فایل نباشد موتور مسیر جعل نمی‌کند: به برند تایپوگرافیک برمی‌گردد و هشدار ثبت می‌کند.
- **موتور جدول (قانون راند ۳):** ارتفاع ردیف‌ها در Chromium اندازه گرفته می‌شود (`measure.mjs`).
  جدولی که در یک صفحه جا می‌شود **هرگز** تقسیم نمی‌شود (اگر در باقیمانده جا نشود کامل به صفحهٔ بعد
  می‌رود و شکست به رندر تحمیل می‌شود). جدول بلندتر از صفحه: تقسیم فقط روی مرز ردیف‌ها + تکرار سربرگ
  + برچسب «ادامهٔ جدول X» با همان شماره. هیچ ردیفی وسط صفحه نمی‌شکند. `col_widths` اختیاری در داده
  پشتیبانی می‌شود؛ جدول‌های پرردیف به‌صورت خودکار فشرده‌تر (بدون کاهش فونت) می‌نشینند.
- **گذر بازخورد PDF واقعی:** بعد از رندر اول بدنه، صفحات کم‌پُر از خود PDF خوانده می‌شوند و شکلِ
  ابتدای صفحهٔ بعد اگر اندکی بزرگ‌تر از فضای خالی باشد، در محدودهٔ خوانایی کوچک می‌شود (حداکثر دو
  دور، بدون جابه‌جایی ترتیب). این گذر رانش «شبیه‌سازی ↔ Chromium» را با شاهد واقعی اصلاح می‌کند.
- **Preflight (در QA):** یکپارچگی هر جدول روی PDF نهایی (عنوان و آخرین ردیف هم‌صفحه؛ برای قطعه‌بندی‌شده
  وجود «ادامهٔ جدول»)، بازبینی نهایی شماره‌های فهرست روی PDF ادغام‌شده (`toc_verified`)، شمارش تصاویر
  محتوایی جدا از دارایی برند، به‌علاوهٔ همهٔ چک‌های قبلی (برند، املا، فونتِ تعبیه‌شده با استخراج واقعی،
  ناحیهٔ امن، پُری، چک‌سام اعداد، حقایق کنترلی). خطاها در `build_report.json`/`review_report.md` ذخیره می‌شوند.
- **سیستم معنایی کادرها:** ۹ نوع ثابت (کلیدی، بالینی، هشدار، از ساختار تا عملکرد، اختلاف منابع،
  امتحانی، تعریف اصطلاح، مثال آموزشی، جمع‌بندی سریع) + بلوک‌های فرایند/دوفراینده به‌عنوان مسیر مرحله‌ای.
  هر نوع: آیکون SVG، رنگ ثابت، برچسب متنی و الگوی حاشیهٔ متمایز برای چاپ سیاه‌وسفید. راهنمای خواندن فقط
  انواع استفاده‌شده در همان جلسه را فهرست می‌کند. برچسب «امتحانی» هرگز خودکار ساخته نمی‌شود.
- **آزمون‌ها:** `tests/test_round3.py` + اسناد مصنوعی `tests/fixtures/` هر ۱۲ سناریوی مرحلهٔ ۸ را پوشش
  می‌دهد (جدول کوتاه/متوسط/بلند، سلول چندخطی، ترکیب فارسی-انگلیسی، شکل بزرگ با زیرنویس، چندمبحثی با
  فهرست، تصویر گمشده با خطای نامی، بازتولید پایدار، لوگو و بازگشت امن نبودِ آن). جمع کل: ۳۶ تست.

**محدودیت‌های صادقانهٔ فعلی:** سلول ادغام‌شده (colspan/rowspan) در مدل محتوا پشتیبانی نمی‌شود؛
صفحهٔ افقی (Landscape) برای جدول‌های خیلی عریض هنوز پیاده نشده (عرض ستون و تقسیم منطقی راه فعلی است)؛
بخش «مراجع پایانی» ساخته نمی‌شود (منابع کنار هر مطلب می‌آیند)؛ خروجی PDF/A ادعا نمی‌شود. محتوای پایلوت
همچنان `needs_review` است و منتظر تأیید تیم علمی.

## راند ۴ — موتور صفحه‌آرایی تطبیقیِ محتوامحور (Content-Aware Adaptive Layout)

اصل: **تنوع در ارائه، ثبات در هویت، پیوستگی در یادگیری** — و هیچ تنوعی بر صحت محتوا غلبه نمی‌کند.

- **تحلیل‌گر معنایی (`engine/humsyar/analyze.py`):** برای هر بازهٔ بخشی، پروفایل ساختاری می‌سازد
  (ترکیب بلوک‌ها، حجم متن، تراکم عدد/اصطلاح لاتین، شکل‌ها، جدول‌ها، کادرها) و کهن‌الگوی ارائه را
  قطعی تعیین می‌کند: توضیحی، مقایسه‌ای، طبقه‌بندی، فرایندی، شکل‌محور، تعریف‌محور، جمع‌بندی یا ترکیبی.
  هیچ تفسیر علمی یا حدس زبانی در کار نیست؛ خروجی در `build_report.json → content_analysis`.
- **کاندید + امتیازدهی (`engine/humsyar/scoring.py` + `config/layout.yaml`):** برای هر شکل و فرایند
  چند کاندید ساخته می‌شود؛ فیلترهای سخت (سقف ارتفاع، کف خوانایی، درخواست صریح داده، نیاز متن لنگر)
  پیش از امتیازدهی اعمال می‌شوند و با وزن قابل دور زدن نیستند. امتیاز از تناسب با کهن‌الگو، نسبت
  ابعاد، خوانایی/DPI، اقتصاد صفحه، تنوع نسبت به همسایه، پیوستگی و ایمنی چاپ ساخته می‌شود.
  وزن‌ها، قرابت‌ها و ترجیحات (حافظهٔ طراحی) در `config/layout.yaml` قابل تنظیم و بازگشت‌اند.
  همهٔ کاندیدها و امتیازها در `layout_decisions` ثبت می‌شوند تا هر انتخاب قابل ممیزی باشد.
- **حافظهٔ چیدمان و کنترلر تنوع:** شبیه‌سازی بسته‌بندی برای هر صفحه «امضای بصری» ثبت می‌کند
  (`page_signatures`)؛ اگر ≥۳ صفحهٔ متوالی هم‌امضا شوند و کاندید تقریباً هم‌امتیاز (≤ اپسیلون کانفیگ)
  با چیدمان دیگر برای شکلی در صفحهٔ میانی باشد، همان تعویض می‌شود و در گزارش می‌نشیند.
- **حلقهٔ بازرسی بصری (`engine/humsyar/inspect.py`):** Render → Inspect → Diagnose → Repair →
  Render Again روی PDF واقعی بدنه، با اندازه‌گیری مختصات: صفحهٔ کم‌پُر، شکاف داخلی (با خط آب، بدون
  مثبت کاذب دوستونه)، تیتر یتیم، جدایی شکل/زیرنویس، تراکم غیرعادی، یکنواختی امضا. اصلاح‌ها هدفمند و
  حداکثر دو دورند؛ باقیمانده‌ها با علت محتمل به QA و `review_report.md` می‌روند.
- **گونه‌های تازهٔ رندر:** نوار افقی فرایند برای فرایندهای کوتاه (در برابر گام عمودی)، ریتم تنفسی
  برای بخش توضیحی بلند، و راهبرد عرض ستون متناسب با آمار طول سلول‌ها — همه با همان توکن‌های برند.
- **اثبات‌ها (`tests/test_round4.py` + فیکسچرهای `adaptive`/`monotony`):** از جمله فرایندِ یکسان که
  در دو بافت متفاوت یک‌بار عمودی و یک‌بار نوار افقی رندر می‌شود و با صفر کردن وزن تنوع برمی‌گردد.
  جمع کل تست‌های پروژه: ۴۷.

**مرز صادقانهٔ هوشمندی:** تحلیل و انتخاب‌ها قاعده‌محور و قطعی‌اند (قابل آزمون و تکرار)، نه فراخوانی
مدل زبانی در زمان اجرا؛ تبدیل متن آزادِ بدون ساختار به جدول/نمودار انجام نمی‌شود چون ریسک ساختن
رابطهٔ علمی دارد. ورودی همچنان مدل ساختاریافتهٔ YAML است و هر تبدیل ارائه‌ای فقط روی همان دادهٔ
موجود انجام می‌شود.

### مرحلهٔ ۱ — توکن‌ها، موجودیت‌ها، ناوبری
- **`config/entities.yaml` + `engine/humsyar/entities.py`:** برای شش سلول گلیال، آکسون/دندریت/میلین،
  CNS/PNS و دو جهت انتقال، رنگ ثابت تعریف شد. تطبیق فقط نام دقیق فارسی/انگلیسی است؛
  رنگ همیشه کنار برچسب متنی می‌نشیند (چاپ سیاه‌وسفید امن). کاربرد: سربرگ جدول‌ها،
  شاخه‌های درخت طبقه‌بندی، ریل‌های نمودار فرایند.
- **صفحهٔ فهرست کامل:** نقشهٔ جلسه + فهرست مطالب + **فهرست شکل‌ها و جدول‌ها** (صفحهٔ واقعی از بدنه
  خوانده می‌شود) + راهنمای خواندن با **نمونهٔ واقعی کادرها**. ارتفاع این صفحه بین گذرهای رندر
  ثابت نگه داشته می‌شود تا شماره‌های فهرست هرگز جابه‌جا نشوند.
- **سرآغاز مبحث:** نوار پیشرفت نقشهٔ جلسه (انجام‌شده/جاری/پیش‌رو) و اهداف با جای تیک ☐.
- **قاب چندواریانتی:** زبانهٔ انگشت‌نما (thumb index) روی لبهٔ بیرونی با آینه‌سازی زوج/فرد برای
  چاپ دورو + نوار پیشرفت مطالعه در پایین هر صفحه. مبحث جاری هر صفحه از فهرستِ راستی‌آزمایی‌شده می‌آید.
- **نشان عددی `[[num:...]]`:** عددِ خود متن (مثل «۶۰ قطعهٔ بین‌گره‌ای»، «ده برابر»، «۴۰۰ میلی‌متر در روز»)
  به‌صورت برجسته رندر می‌شود؛ در کادر اختلاف منابع، هر دو عدد متقارن نشان می‌گیرند تا بی‌طرفی حفظ شود.
- **نسخهٔ کم‌جوهر چاپی:** `--print-theme` → پسوند `_print` (داخل تخت و روشن، جلد همان تیره).

### مرحلهٔ ۲ — اجزای یادگیری فعال (بدون حتی یک واژهٔ علمی تازه)
- **`tldr` (در یک نگاه):** جملهٔ محوری باید **عین یکی از جمله‌های همان بخش** باشد.
- **`quick_check` (خودآزمایی سریع):** جای‌خالی روی اصطلاح/عددِ همان جملهٔ متن؛ پاسخ فقط در
  پاسخ‌نامهٔ پایان جلسه می‌آید. هر دو بلوک در پایلوت با `provisional: true` و وضعیت `needs_review`
  آمده‌اند و نوار «پیشنهاد برای تأیید تیم علمی» دارند. تست خودکار ثابت می‌کند جای‌گذاری پاسخ
  در جای خالی، عین جملهٔ اصلی متن می‌شود.
- **واژه‌نامهٔ فارسی–انگلیسی پایان جلسه:** فقط اصطلاح‌های خود جلسه (اصطلاحات کلیدی مباحث،
  برچسب‌های شکل‌ها، `[[term:]]`های درون‌متن) با صفحهٔ نخستین کاربرد؛ تعریف ساخته نمی‌شود.
- **شناسنامهٔ نسخه (کولوفون):** درس/جلسه/مباحث/نسخه/منابع/وضعیت بازبینی — همه از دادهٔ جلسه؛
  نام اشخاص یا نشانی تماس ساخته نمی‌شود.

### مرحلهٔ ۳ — نمودار برداری از داده
- بلوک `dual_process` حالا یک **نمودار ریلی SVG** می‌سازد: دو پیکان موازی خلاف‌جهت با رنگ ثابت
  آنتروگرید/رتروگرید، سوما در راست و پایانه در چپ (جهت علمی سوما→پایانه حفظ می‌شود) و
  برچسب‌ها عین عنوان‌های داده. درخت طبقه‌بندی هم شاخه‌های هم‌رنگ موجودیت‌ها گرفت
  (میکروگلیا همچنان خط‌چینِ استثناست).

### مرحلهٔ ۵ — QA سخت‌تر و حجم کمتر
- چک‌سام اعداد حالا اسپن‌به‌اسپن هم شمرده می‌شود (چسبیدن ارقام به شماره‌صفحهٔ چیپ منبع، گم‌شدن کاذب نمی‌سازد).
- یکپارچگی جدول با هم‌مکانی «عنوان + ردیف نخست + ردیف آخر» در یک صفحه اثبات می‌شود.
- یابندهٔ صفحهٔ سرفصل پروب قوی (چهار واژهٔ فارسی نخست عنوان) گرفت؛ راستی‌آزمایی نهایی فهرست بدون هشدار کاذب.
- `garbage=4` در ذخیرهٔ نهایی: حذف تکثیر جریان فونت واریانت‌های قاب (۵٫۳MB ← ۲٫۶MB).
- چک‌لیست چاپ: کاغذ A4، حاشیهٔ صحافی در قاب رعایت شده، زبانه‌ها برای دورو آینه می‌شوند،
  نسخهٔ `_print` برای چاپ کم‌جوهر، فونت‌ها تعبیه و متن قابل جست‌وجو/کپی است.

### مرزهای صادقانهٔ راند ۵
ستارهٔ اهمیت و زمان مطالعه ساخته نشد (داده‌ای در جزوه نیست)؛ QR/پیوند بیرونی ساخته نشد
(نشانی‌ای داده نشده)؛ تصویرهای مادر با نمودار اختراعی جایگزین نشدند؛ برگهٔ تقلب/فلش‌کارت/نمایه
به محتوای تأییدشدهٔ تیم علمی نیاز دارد و در نقشهٔ راه می‌ماند. پایلوت ۱۳←۱۶ صفحه شد
(مادهٔ پایانی و بلوک‌های یادگیری واقعی‌اند، نه بادکردن صفحه)؛ میانگین پُری ۸۸٪ و تنها صفحهٔ
زیر ۷۰٪ صفحهٔ پایان مبحث ۶ است (۶۴٪) که پیش از صفحهٔ جمع‌بندیِ درخت‌دار قرار دارد و در QA هشدار می‌گیرد، پنهان نمی‌شود.


## راند ۶ — زبان بصری معنایی و نسخهٔ نهایی

### تصمیم‌های محصولی این نسخه
- **خودآزمایی سریع از این جزوه حذف شد** (تصمیم مالک محصول برای نسخهٔ نهایی). موتور هنوز
  بلوک `quick_check` را به‌صورت opt-in پشتیبانی می‌کند (سطح P3) ولی در این سند استفاده نشده
  و پاسخ‌نامه‌ای هم چاپ نمی‌شود. برچسب «پیشنهاد برای تأیید تیم علمی» و مکانیزم آن حذف شد؛
  بلوک‌های «در یک نگاه» که عین جمله‌های متن بودند، به‌عنوان جزء نهایی ماندند.
- **حس نسخهٔ نهایی در سراسر سند:** وضعیت انتشار از خود سند می‌آید (`draft: false`) —
  نشان «پایلوت موتور» از کاور رفت، شناسنامه «نسخهٔ نهایی» می‌گوید و نسخهٔ جزوه ۱٫۰ شد.

### کتابخانهٔ آیکون SVG (`engine/humsyar/icons.py`)
مخزن مرکزی ۲۷ آیکون خط‌محور روی شبکهٔ ۲۴×۲۴ با `currentColor` — بدون فونت آیکون و منبع
خارجی، پس در چاپ و نمایشگر یکسان‌اند و هرگز به مربع خالی تبدیل نمی‌شوند. هر آیکون شناسهٔ
پایدار و معنای فارسی ثبت‌شده دارد. گونه‌های کادر معنایی از ۹ به **۱۴** رسید: + استثنا، یادیار،
فرمول، اصطلاح‌شناسی، نیازمند بررسی — هر کدام با آیکون ثابت، توکن رنگ و الگوی مرزی متمایز
برای چاپ سیاه‌وسفید. قانون ثابت می‌ماند: گونه فقط با تطابق محتوایی، و برچسبی مثل
«نکتهٔ امتحانی» فقط وقتی خود منبع چنان جایگاهی داده باشد.

### اصلاح ریشه‌ای قاب جدول
علت ناهماهنگی دور جدول، سه سیستم هم‌پوشان بود: بوردر کامل دور هر سلول، راه‌راه سراسری،
و خط زیر سربرگ با وزن متفاوت برای ستون‌های موجودیتی (۲٫۲pt در برابر ۱px). حالا **مالک
قاب فقط wrapper است**: قاب گرد یکدست دور عنوان+جدول، داخل فقط خطوط مویی، خط زیر سربرگ
در همهٔ ستون‌ها هم‌وزن (۲pt؛ رنگ هر قطعه = رنگ موجودیت همان ستون)، و راه‌راه فقط در
سبک مرجع. نتیجه روی جدول مقایسهٔ آکسون/دندریت با رندر بزرگ‌نمایی تأیید شد.

### رنگ و زندگیِ کنترل‌شده
- راهنمای خواندن حالا **راهنمای رنگ ثابت مفاهیم همین جلسه** را هم دارد (فقط موجودیت‌های
  واقعاً به‌کاررفته).
- چیپ‌های برچسب شکل و ردیف‌های واژه‌نامه برای موجودیت‌های شناخته‌شده **نقطهٔ رنگی و
  قاب هم‌رنگ** می‌گیرند؛ همان رنگی که در جدول و درخت دیده می‌شود.
- واژه‌نامه فشرده‌تر شد (فونت و فاصلهٔ خط کمتر) تا فضای کمتری بگیرد.

### نوار پیشرفتِ چاپ‌امن
نوار پیشرفت پایین صفحه حالا **از راست پر می‌شود** (جهت خواندن فارسی)، شیار سفید با قاب
تیره دارد و پُری‌اش سرمه‌ای تیره است تا در چاپ سیاه‌وسفید هم «نواری در حال پرشدن» خوانده
شود — با رندر خاکستری و تست هندسی روی PDF واقعی تأیید شده است.

### وضعیت و مرزها
۱۵ صفحه، میانگین پُری ۸۹٪، QA ✅ در هر چهار نسخه (نهایی/کاربرگ/تم B/چاپی)، مجموعه تست
**۷۰/۷۰**. تنها صفحهٔ زیر ۷۰٪، صفحهٔ پایان مبحث ۴ است (۶۱٪) چون سرآغاز مبحث ۶ یک واحد
معناییِ نشکنِ بلندتر از باقیماندهٔ صفحه است؛ در گزارش QA با هشدار آشکار می‌ماند.
حاشیهٔ یادداشت دانشجو، فلش‌کارت و QR همچنان P2/P3 و وابسته به محتوای تأییدشده‌اند.


## راند ۷ — نقشهٔ جامع مرور (Master Revision Map)

### اصل بنیادین: پوشش کامل، بدون خلاصه‌سازی سلیقه‌ای
موتور تازه (`engine/humsyar/revision.py`) محتوای علمی جلسه را به‌صورت **مکانیکی و
بی‌اتلاف** به گزاره‌های قابل ردیابی تجزیه می‌کند: هر جملهٔ پاراگراف، هر ردیف جدول،
هر گام فرایند، هر کادر، هر برچسب شکل و هر جملهٔ توضیح شکل یک گزاره با شناسهٔ پایدار
است و متنش **عین عبارت منبع** است — هیچ بازنویسی، تفسیر یا مخفف‌سازی رخ نمی‌دهد.
تست خودکار ثابت می‌کند چسباندن دوبارهٔ گزاره‌های هر پاراگراف، عین متن پاراگراف می‌شود.

### ماتریس پوشش (Content Coverage Matrix)
هر گزاره به گرهٔ نقشه (بخش خودش) تخصیص می‌یابد و وضعیت می‌گیرد:
- `covered`: در پنل جزئیات همان بخش چاپ شده است.
- `unresolved`: ماشینی قابل نمایش نیست — فقط جزئیات درون پیکسل‌های تصویر، فراتر از
  برچسب‌هایش؛ این‌ها حذف نمی‌شوند، در نقشه با نشانهٔ میکروسکوپ به خود شکل و صفحه‌اش
  ارجاع داده می‌شوند و در QA هشدار شفاف می‌گیرند.
- `unassigned`: نباید هرگز رخ دهد؛ اگر رخ دهد QA خطا می‌دهد و بیلد «کامل» اعلام نمی‌شود.

گزارش کامل در `build_report.json → coverage` است. بلوک‌های مشتق نمایشی (`tldr` و درخت
طبقه‌بندی) خودشان نمایی از همان محتوا هستند و برای جلوگیری از دوباره‌شماری، صریحاً
خارج از جهان پوشش ثبت می‌شوند. برای پایلوت: **۱۸۷ گزاره، ۱۷۶ پوشیده، ۱۱ ارجاع تصویری،
صفر بی‌گره**.

### معماری دوسطحی نقشه
- **سطح ۱ — ساختار:** درخت طبقه‌بندی جلسه (موجود) + سربرگ هر پنل با عنوان بخش و
  شمارهٔ صفحهٔ متن کامل.
- **سطح ۲ — جزئیات کامل:** پنل‌های فشردهٔ هر بخش با همهٔ گزاره‌ها؛ استثناها با مرز
  نقطه‌چین نارنجی، اختلاف منابع با قاب خط‌چین قرمز، گزاره‌های عدددار با نشانهٔ Σ،
  گام‌های فرایند شماره‌دار، و ردیف‌های جدول با زیرعنوان جدول خودشان.

فونت نقشه زیر کف خوانایی نمی‌رود؛ اگر محتوا در یک صفحه جا نشود نقشه به‌صورت
چندصفحه‌ای کامل ادامه پیدا می‌کند (حالت C بریف) — صفحهٔ شلوغِ ناخوانا موفقیت نیست.
برای پایلوت، نقشه ۵ صفحهٔ متراکم (۹۲ تا ۹۹٪ پُری) شد و سند به ۲۰ صفحه رسید.
روشن/خاموش‌کردن از `config/layout.yaml → revision_map.enabled` است.

### مرز صادقانه
سلسله‌مراتب مفهومیِ آزاد (مثلاً ساختن درخت مفهومی تازه از متن خام) عمداً خودکار نشده
است، چون نیازمند تفسیر و بازنویسی علمی است و با قانون طلایی پروژه ناسازگار است.
ساختار نقشه همان ساختار واقعی سند (مبحث ← بخش) است و درخت مفهومیِ تألیف‌شدهٔ جلسه
همچنان سطح اول بازیابی سریع می‌ماند. گونه‌بندی گزاره‌ها فقط با نشانه‌های صریح متنی
انجام می‌شود (مثلاً واژهٔ «استثنا»)؛ بقیه «جزئیات» می‌مانند و حدس زده نمی‌شود.

## راند ۸ — اصلاحات محصول (فونت لاتین، حذف رنگ واژه‌ها، زبانهٔ یک‌طرفه)

- **فونت لاتین Inter** (Regular/Italic/Medium/SemiBold/Bold، WOFF2 از Fontsource،
  لایسنس OFL در `assets/fonts/Inter-LICENSE.txt`) جایگزین DejaVu Sans شد؛ رنگ
  واژه‌های لاتین در همه‌جا **تیره** (`#22384F`) است، نه آبی. Inter جفت استاندارد
  وزیرمتن در محصولات فارسی است. گلیف‌های نمادین (مثلث‌های جهت، مربع چک‌لیست)
  به‌صورت برداری کشیده می‌شوند تا هیچ فونت جایگزینی وارد PDF نشود (تست تعبیه).
- **رنگ‌بندی واژه‌ها حذف شد** (تصمیم محصول، وارونهٔ راند ۵/۶): راهنمای «رنگ ثابت
  مفاهیم»، نقطه/قاب رنگی چیپ‌ها و واژه‌نامه، و رنگ سربرگ‌های جدول برداشته شد؛
