# HumsYar PDF Engine — موتور جزوه‌ساز هامزیار

موتور تولید جزوات علوم پایهٔ پزشکی: «جزوهٔ مادر» هر جلسه را به PDF نهایی حرفه‌ای تبدیل می‌کند —
مدل محتوای ساختاریافته + Design System فارسی/RTL + موتور چیدمان + رندر Chromium + QA خودکار.

گزارش ممیزی و تصمیم‌های معماری: [`docs/AUDIT.md`](docs/AUDIT.md) · مشخصات پروژه: [`docs/AGENT_PROMPT.md`](docs/AGENT_PROMPT.md)

## اجرای سریع

```bash
python3 -m venv .venv && .venv/bin/pip install -r engine/requirements.txt pillow
cd engine && npm install        # puppeteer-core + Chromium بسته‌بندی‌شده (آفلاین‌پسند)
# اگر Chrome سیستمی دارید، به‌جای npm کافی است: export CHROME_PATH=/path/to/chrome

# ساخت پایلوت (جلسهٔ ۱، مباحث ۴ و ۶)
../.venv/bin/python -m humsyar.cli build ../content/session01_pilot.yaml --edition final --out ../output

# تست‌ها
cd .. && .venv/bin/python -m pytest tests/ -q
```

خروجی‌ها در `output/`: فایل PDF، نسخهٔ HTML، `build_report.json` (تصمیم‌های چیدمان + QA)،
`review_report.md` (موارد نیازمند بازبینی انسانی) و رندر تصویری صفحات در `output/pages/`.

## گزینه‌های ساخت

| پرچم | مقادیر | پیش‌فرض | توضیح |
|---|---|---|---|
| `--edition` | `final` / `workbook` | `final` | workbook کادرهای یادداشت تیم را نگه می‌دارد |
| `--theme` | `a` / `b` | `a` | A: تیل بالینی · B: سرمه‌ای تحریریه‌ای (فقط توکن رنگ) |
| `--no-sources` | — | خاموش | پنهان‌کردن برچسب‌های منبع |

## استخراج از جزوهٔ مادر

```bash
../.venv/bin/python -m humsyar.cli extract ../HumsYar_NeuroAnat_Jalase1.pdf --out ../audit/s01
```

خروجی «پیش‌نویس استخراج» است (متن با ترتیب منطقی بازسازی‌شده + تصاویر اصلی + فهرست وضوح)؛
ساختاربندی آن به YAML گام ویرایشی جداست و وضعیت همهٔ بلوک‌ها تا تأیید تیم `needs_review` می‌ماند.

## افزودن جلسهٔ جدید

۱) استخراج (بالا) ← ۲) ساختاربندی در `content/sessionXX.yaml` با همان قرارداد بلوک‌ها ←
۳) `build` ← ۴) خواندن `review_report.md` و رندر صفحات ← ۵) تأیید علمی و تغییر وضعیت بلوک‌ها به `approved`.
هیچ تغییری در کد لازم نیست.

## قرارداد محتوای YAML (خلاصه)

هر بلوک: `id` پایدار، `type`، `status` (`extracted|editorial|needs_review|approved|unresolved_conflict`)،
`sources: [{book, pages, figure}]` و فیلدهای خودش. انواع بلوک: `section, paragraph, callout
(key|clinical|warning|bridge|conflict|exam), table, figure, process, dual_process, tree,
checklist, summary_box, team_note`.

نشانه‌گذاری درون‌متنی: `**برجسته**` · `[[term:فارسی|English]]` (اصطلاح دوزبانه) · `[en:Na+/K+-ATPase]` (لاتین ایزوله برای سلامت bidi).

**قانون محتوا:** موتور هرگز عدد/اصطلاح/مطلب علمی را تغییر نمی‌دهد و اختلاف منابع را حل نمی‌کند؛
ابهام‌ها در `review_report.md` ثبت می‌شوند.

## ساختار مخزن

```

```

## راند ۲ — کاور، فهرست، قاب موضوعی و تراکم (نسخهٔ ۰٫۲ پایلوت)

**قانون برند:** تنها املای درست «هامزیار / HumsYar» است و از یک منبع مرکزی خوانده می‌شود:
`config/brand.yaml` (`engine/humsyar/brand.py`). تست خودکار برند روی متن PDF نهایی، متادیتا
و کل ریپو (به‌جز پرامپت آرشیوی کارفرما و استخراج‌های جزوهٔ مادر در `audit/` که سند تاریخی‌اند)
باید صفر باشد. لوگوی رسمی در ریپو وجود ندارد؛ برند صرفاً تایپوگرافیک است.

**خط لولهٔ جدید build:**
`validate → brand → بهینه‌سازی تصاویر نمایشی → planner v2 → measure (ارتفاع واقعی بلوک‌ها در Chromium) → packing (شبیه‌سازی صفحه‌بندی + اصلاح‌های مجاز) → رندر بدنه → شماره‌صفحه‌های واقعی فهرست → رندر نهایی بدنه → رندر جدا کاور و قاب → ادغام و مهر (PyMuPDF) → بوکمارک/متادیتا → QA`

- **کاور (ص.۱):** تمام‌صفحه (full-bleed)، هنر پارامتریک SVG با موتیف قابل‌پیکربندی هر جلسه
  (`session.cover_motif`؛ جلسهٔ ۱: `histology-neuron-glia` در `engine/humsyar/cover.py`).
  بدون قاب/شمارهٔ صفحه؛ در شمارش صفحات هست ولی شماره نمی‌گیرد. نشان «پایلوت موتور» فقط با `draft: true`.
- **فهرست (ص.۲ مستقل):** نقشهٔ جلسه + فهرست لینک‌دار با شماره‌صفحهٔ نهایی و نقطه‌چین +
  **تصمیم:** نوار فشردهٔ «چطور این جزوه را بخوانیم؟» پایین همین صفحه نشست (نه ابتدای ص.۳) چون صفحهٔ
  فهرست فضای کافی داشت و خواننده راهنما را پیش از شروع می‌بیند. پیوندها از مختصات واقعی
  اندازه‌گیری‌شده در مرورگر مهر می‌شوند.
- **قاب موضوعی (`session.frame_theme`؛ `engine/humsyar/frame.py`):** قاب دوخطه در اینسِت ۶mm،
  موتیف دندریت/سیناپس در گوشه‌ها (≤۱۱mm)، آکسون+میلین روی لبهٔ بالا، تب سربرگ روی خط بالا،
  کپسول شمارهٔ صفحه وسط خط پایین (فقط رقم فارسی، مهرشده با TextWriter). مقدار `none` پشتیبانی می‌شود.
- **عرض مفید صفحه:** حاشیهٔ داخلی ۱۴/۱۳mm → عرض مفید متن **۱۸۲mm** (راند ۱: ۱۷۸mm؛ +۴mm).
  ناحیهٔ امن QA: ‏(۱۲،۱۲) تا (۱۹۸،۲۸۵) میلی‌متر. قد مفید ≈ ۲۷۰mm.
- **قواعد تراکم پلنر v2:** سقف ارتفاع تصویر پهن ≈۸۶mm (۳۲٪)، عمودی/مربعی ≈۱۱۳mm (۴۲٪)،
  سقف سخت ≈۱۲۱٫۵mm (۴۵٪)؛ پیش‌فرض تصویر عمودی/مربعی: «کپشن‌کناری»؛ زوج‌شکل هم‌مبحث وقتی در
  نیم‌عرض خوانا بماند؛ `min_width_mm` برای شکل‌های برچسب‌دار؛ عملیات بسته‌بندی فقط: کوچک‌سازی
  در محدودهٔ خوانایی، جلوکشیدن بلوک مستقل از پنجرهٔ ۳تاییِ همان بخش (بدون شکستن ارجاع به شکل)،
  شکست کنترل‌شدهٔ جدول بزرگ. ترتیب معنایی و لینک تصویر-متن هرگز نمی‌شکند.
- **نتیجهٔ پایلوت:** ۱۳ صفحه (کاور+فهرست+۱۱ بدنه) در برابر ۱۶ صفحهٔ راند ۱؛ میانگین پُری صفحات
  محتوایی ≈۹۳٪ و هیچ صفحهٔ محتوایی زیر ۷۰٪ نیست (گزارش ریز در `output/build_report.json`).

**استثنای مستند برچسب‌های ریز:** در دو میکروگراف (`s01t6-f5` و `s01t6-f9`) برچسب‌های *داخل* تصویر
در هیچ اندازهٔ معقول چاپی به کف ۶٫۵pt نمی‌رسند (حتی تمام‌صفحه)؛ بنابراین کانال خوانایی، «چیپ‌های
دوزبانهٔ برچسب» کپشن است که همهٔ برچسب‌های متن مادر را با فونت خوانا بازمی‌نویسد. کف‌های حدسی
`min_width_mm` این دو شکل حذف شد تا چیدمان کپشن‌کناری کار کند؛ اصل تصویرها دست‌نخورده‌اند.

تست‌های راند ۲ در `tests/test_round2.py`: قانون برند (PDF+متادیتا+ریپو)، لینت همزهٔ اضافه،
نمونه‌برداری پیکسلی کاور، لینک‌های فهرست، رقم فارسی کپسول، ناحیهٔ امن قاب، سقف‌های پلنر،
قطعیت بسته‌بندی و معیارهای پُری.
