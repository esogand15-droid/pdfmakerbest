# نقشهٔ معماری موتور PDF هامزیار (HumsYar PDF Engine)

> سند مرحلهٔ ۱ ارتقای حرفه‌ای (راند ۳): ردیابی مسیر تولید، مسئولیت ماژول‌ها،
> محدودیت‌های شناخته‌شده و نقاط مستعد خطا. مبنای مقایسه: `output/baseline_round2.pdf`.

## مسیر تولید (Pipeline)

```
YAML محتوا
  → model.load_session + validate        (مدل معنایی + اعتبارسنجی)
  → brand.load_brand(config/brand.yaml)  (تنها منبع نام/دارایی برند)
  → build._optimize_figures              (نسخهٔ نمایشی JPEG؛ اصل تصاویر دست‌نخورده)
  → planner.plan_session                 (شماره‌گذاری شکل/جدول، انتخاب چیدمان، سقف ارتفاع)
  → typeset (گذر A) + measure.mjs        (ارتفاع واقعی هر بلوک در Chromium، میلی‌متر)
  → packing.pack                         (شبیه‌سازی صفحه‌بندی + اصلاح‌های مجاز و لاگ‌شده)
  → typeset + render.mjs (بدنه)          (Chromium/Puppeteer، حاشیهٔ ۱۴/۱۳mm)
  → جست‌وجوی صفحهٔ واقعی تیترها           (شماره‌های فهرست از PDF واقعی + آفست کاور)
  → typeset + render (بدنهٔ نهایی)        (فهرست با شمارهٔ درست)
  → cover.py / frame.py (رندر جدا، حاشیه ۰)
  → PyMuPDF: ادغام کاور، مهر قاب و کپسول شماره، لینک‌های فهرست، بوکمارک، متادیتا
  → qa.run_qa (Preflight) + گزارش‌ها + رندر تصویری صفحات
```

## مسئولیت ماژول‌ها

| ماژول | مسئولیت |
|---|---|
| `humsyar/model.py` | Content Model: Session/Topic/Block/Source، اعتبارسنجی، نرمال‌سازی متن |
| `humsyar/brand.py` + `config/brand.yaml` | تنها منبع نام برند و مسیر دارایی‌های برند (لوگو) |
| `humsyar/planner.py` | Layout Planner: شماره‌گذاری پایدار، سقف ارتفاع تصویر، چیدمان full/sidecap/side/pair |
| `humsyar/packing.py` | Layout Engine: شبیه‌سازی صفحه‌بندی با ارتفاع واقعی؛ سیاست Keep/شکست جدول و شکل |
| `engine/measure.mjs` | اندازه‌گیری ارتفاع بلوک‌ها (و ردیف‌های جدول) در Chromium با مدیای چاپ |
| `humsyar/typeset.py` | Components: رندر HTML بلوک‌ها (کادر معنایی، جدول، شکل، فرایند، درخت، چک‌لیست) + bidi |
| `humsyar/diagrams.py` | نمودار درختی SVG داده‌محور |
| `themes/humsyar.css` | Design Tokens تم A (Clinical Teal) و B؛ قانون: تغییر تم = تغییر توکن |
| `humsyar/cover.py` | جلد تمام‌صفحه: هنر پارامتریک SVG + لوگوی برند + سلسله‌مراتب عنوان |
| `humsyar/frame.py` | قاب موضوعی صفحات، تب سربرگ، کپسول شمارهٔ صفحه |
| `humsyar/build.py` | Document Composer: ارکستراسیون گذرها، ادغام، مهر، بوکمارک، متادیتا، گزارش |
| `humsyar/qa.py` | PDF Validator / Preflight: پوشش محتوا، برند، املا، فونت، ناحیهٔ امن، پُری، یکپارچگی جدول |

## فناوری رندر و دلیل انتخاب

- **Chromium (Puppeteer)** — تنها گزینهٔ قابل اتکا در این محیط برای شکل‌دهی فارسی/RTL و
  Bidi صحیح (Bake-off راند ۱: WeasyPrint به‌علت نبود Pango/Cairo رد شد؛ ReportLab شکل‌دهی
  فارسی ندارد). فونت Vazirmatn (مجوز OFL، در `assets/fonts/OFL.txt`) در PDF جاسازی می‌شود.
- **PyMuPDF** فقط برای پس‌پردازش (ادغام/مهر/لینک/بوکمارک/بازرسی) — هرگز برای شکل‌دهی متن فارسی.

## سیاست صفحه‌بندی بلوک‌ها (خلاصه)

- تیتر بخش + آغاز بلوک بعد: هم‌صفحه (`break-after: avoid` + قاعدهٔ شبیه‌سازی).
- شکل+کپشن، کادرها، فرایند، درخت، چک‌لیست: واحد نشکن.
- **جدول:** اگر ارتفاع کل (عنوان+سربرگ+ردیف‌ها) ≤ ارتفاع مفید صفحه → واحد نشکن؛ اگر در
  باقی‌ماندهٔ صفحه جا نشود، کامل به صفحهٔ بعد می‌رود («شکست قبل از جدول» از شبیه‌سازی
  تزریق می‌شود، نه حدس CSS). اگر از یک صفحه بلندتر است → تقسیم کنترل‌شده فقط روی مرز
  ردیف‌ها، تکرار سربرگ ستون‌ها و برچسب «ادامهٔ جدول X»؛ شمارهٔ جدول عوض نمی‌شود.
  هیچ ردیفی از وسط نمی‌شکند (`tr { break-inside: avoid }` + برش ردیف‌محور در تایپ‌ست).

## محدودیت‌های شناخته‌شده و نقاط مستعد خطا

1. **رانش شبیه‌سازی ↔ Chromium:** ارتفاع‌های اندازه‌گیری‌شده در مدیای screen با عرض معادل
   چاپ گرفته می‌شوند؛ orphans/widows و گردکردن‌های چاپ می‌توانند چند میلی‌متر اختلاف بسازند.
   راه‌حل فعلی: ارتفاع امن شبیه‌سازی ۲۶۶ از ۲۷۰mm + سقف‌های محافظه‌کار پلنر + QA روی PDF واقعی.
2. **استخراج متن PDF** (برای QA) نویز دارد: لا→ال، جابه‌جایی اعراب، چسبیدن لاتین. پوشش محتوا
   با سه‌گرم نویسه‌ای + چکسام اعداد سنجیده می‌شود، نه تطابق رشته‌ای (مستند در راند ۱).
3. **مهر قاب/کپسول با PyMuPDF:** رقم کپسول با TextWriter و فونت تعبیه‌شدهٔ صریح زده می‌شود
   (insert_textbox در راند ۲ بی‌صدا خالی ماند). لینک‌های فهرست از مختصات مرورگر مهر می‌شوند
   چون جست‌وجوی متنی فارسی در PDF قابل اتکا نیست.
4. `position: fixed` در چاپ Chromium برای اسباب صفحه قابل اتکا نیست (تست و رد شده) —
   به‌جایش Overlay جدا رندر و مهر می‌شود.
5. محتوای پایلوت از استخراج PDF مادر بازسازی شده و وضعیتش `needs_review` است؛ موتور هرگز
   متن علمی، عدد یا منبع را تغییر نمی‌دهد و اختلاف منابع را حل نمی‌کند.

## قراردادهای پایداری

- خروجی از ورودی یکسان قطعی است (بذر تصادفی کاور ثابت؛ تست قطعیت تایپ‌ست و بسته‌بندی).
- هر تصویر مدل دقیقاً یک‌بار در خروجی می‌آید (تست QA).
- شماره‌گذاری شکل/جدول توسط پلنر و پایدار است؛ در دادهٔ محتوا دستی نوشته نمی‌شود.
- برند فقط «هامزیار / HumsYar» و فقط از `config/brand.yaml`.


## راند ۴: لایهٔ تطبیقی محتوامحور

```
analyze.analyze_session   → پروفایل و کهن‌الگوی هر بخش (پیش از پلنر)
scoring + planner         → کاندیدهای چیدمان + امتیاز قطعی + فیلتر سخت + لاگ تصمیم
packing (شبیه‌سازی)        → page_map و امضای بصری صفحات + کنترلر تنوع (تعویض ≤ اپسیلون)
build: حلقهٔ بازرسی        → inspect_body (مختصات واقعی PDF) → repair_body/feedback → رندر مجدد (≤۲ دور)
گزارش                     → content_analysis / layout_decisions / page_signatures / inspection
پیکربندی طراحی            → config/layout.yaml (وزن‌ها و ترجیحات؛ قابل بازگشت، بدون قاعدهٔ علمی)
```

قراردادها: امتیازدهی و تحلیل قطعی‌اند (ورودی یکسان ← تصمیم یکسان؛ تست دارد)؛ تنوع فقط وقتی
اعمال می‌شود که کیفیت آموزشیِ کاندید جایگزین تقریباً برابر باشد؛ بازرسی بصری روی PDF واقعی با
اندازه‌گیری انجام می‌شود و یافتهٔ اصلاح‌نشده هرگز پنهان نمی‌شود (به QA می‌رود).


## راند ۵: لایهٔ معنای بصری و یادگیری فعال

- **موجودیت‌ها (`config/entities.yaml`):** تک‌منبعِ «نام دقیق ← رنگ ثابت». `entities.py` فقط تطبیق
  دقیق می‌کند و متغیرهای CSS (`--ent-*`) تولید می‌کند؛ کامپوننت‌ها (سربرگ جدول، درخت، ریل فرایند)
  رنگ را از همین‌جا می‌گیرند و هیچ رنگ موجودیتی در کد هاردکد نیست.
- **بلوک‌های یادگیری (`tldr`/`quick_check`):** در `BLOCK_TYPES` ثبت‌اند؛ رندر در `typeset.py`.
  قاعدهٔ اشتقاق (جملهٔ عینی/جای‌خالی روی جملهٔ عینی) با `provisional` و `needs_review` علامت می‌خورد
  و در `tests/test_round5.py` به‌صورت مکانیکی اثبات می‌شود. پاسخ‌نامه از همان رندر جمع و در پایان سند چاپ می‌شود.
- **مادهٔ پایانی خودکار:** واژه‌نامه (از `key_terms` + برچسب شکل‌ها + `[[term:]]`ها، با صفحهٔ نخستین
  کاربرد از `toc_pages`) و شناسنامه (از فراداده و منابع واقعی جلسه) در `Typesetter.document` ساخته
  می‌شوند؛ در گذر اندازه‌گیری جای شماره‌ها «…» است تا ارتفاع سند بین گذرها ثابت بماند.
- **قاب چندواریانتی:** `build._page_topics` مبحث جاری هر صفحه را از فهرست راستی‌آزمایی‌شده می‌دهد؛
  برای هر (مبحث، زوج/فرد) یک واریانت قاب با زبانهٔ انگشت‌نما رندر و در `_stamp_furniture` مهر می‌شود؛
  نوار پیشرفت هندسهٔ برداری خالص است و همان‌جا کشیده می‌شود.
- **ثبات دوگذری:** هر محتوای وابسته به شمارهٔ صفحه (فهرست شکل‌ها/جدول‌ها، واژه‌نامه) در همهٔ گذرها با
  همان ساختار رندر می‌شود؛ فقط مقدار عدد عوض می‌شود. نقض این قاعده = جابه‌جایی شماره‌های فهرست.
